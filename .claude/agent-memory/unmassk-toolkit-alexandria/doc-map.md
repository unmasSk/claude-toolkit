## Durable lessons (apply regardless of which zone I'm in)

- **A "how we recover from X" / safety-net section reads as plausible and doesn't get challenged like a feature claim does.** Actively grep for the implementing code behind recovery/safety-net prose, don't just check it's internally consistent. (Origin: `unmassk-gitmemory/SKILL.md`'s fictional "Self-Healing (rebase/reset detection)" section, issue #63, 2026-07-11 — described amnesia/history-rewrite detection that never existed as code, undetected through prior passes.)
- **A task brief's "X passed cleanly" claim about a Moriarty/Cerberus review must be checked against that agent's own `MEMORY.md` "Last attack"/review-history entry directly.** This project's worst-case failure pattern is "marked closed, wasn't" — and it repeats as selective citation of only the HELD parts of a verdict while silently dropping the FALLA parts it came bundled with. (2026-08-03, DEUDA.md point 13.)
- **When a task hands over a scoped list of line-numbered fixes, check whether the surrounding paragraph in the target doc refers to a *different, more recent* decision than the one named in the brief.** `git log`/code beats the task prompt's own framing when they disagree; a "decisiones tomadas hoy" list is not guaranteed complete within the same day. (2026-08-03, `PIEZAS.md`.)
- **`docs/plan/*.md` is a LIVE tracker, not frozen history like `docs/deprecated/`.** No "no se mantiene" disclaimer, files get edited on ongoing dates, and they use their own dated "[YYYY-MM-DD] Superseded:" convention. Treat it exactly like any other live doc for staleness — do not skip it as if it were an archive.
- **`unmassk-core/SKILL.md`, `unmassk-gitmemory`-era docs, `unmassk-audit/SKILL.md`'s BM25 lines, and all 9 `agents/*.md` are orchestrator-owned.** Flag drift, never edit directly (standing instruction, reconfirmed every pass since 2026-07-12).
- **`bin/release.py` promotes `## [Unreleased]` to `## [N.N.N] - <date>` itself.** CHANGELOG content always goes straight under `## [Unreleased]` — never write a manual version header, or `release.py` sees an empty `[Unreleased]` and aborts. (Learned the hard way 2026-08-25, first pass of that day.)
- **A "not fixed, flagged" memory entry needs a re-check before it's trusted as still open** — see the `unmassk-memory/SKILL.md` example directly below: flagged not-fixed on 2026-08-25, fixed same day in commit `54a244e`, and the flag survived uncorrected in memory until this compaction pass caught it by re-grepping. Stale "still open" claims are exactly as dangerous as stale "already done" ones.
- **Root `CLAUDE.md`'s own roadmap prose ("Lo que queda por hacer") is a claim, not a fact, and it rots between sessions.** 2026-08-26 close pass: the previous close's own `[NEXT]` named 3 parked fronts (walls audit, agent-memory compaction, Yoda pass); this session's commits closed all 3 (`7525183`, `M-127`), but the roadmap paragraph still said "no ejecutado" for the compaction item — pulled the nouns from the sentence, searched `gitmem`/`git log` per the system-prompt protocol, found the closing commits, corrected the paragraph. Do this every close, not just when something feels off.
